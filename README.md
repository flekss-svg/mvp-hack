# Предиктор задержек наземного транспорта

Сервис заранее предупреждает диспетчера: **эта машина сейчас идет по графику, но через 10–15 минут опоздает больше чем на 3 минуты**. Прогноз строится по потоку событий «машина прошла остановку» и показывается на дашборде вместе с картой, списком тревог и проверкой прошлых тревог.

**Статус:** расписание реальное (data.mos.ru), движение машин пока смоделировано. Приемник телематики NDTP проверен с эмулятором организаторов. Модель под метрику хакатона (MAE) лежит отдельно, в `scripts/`.

## Быстрый старт

Нужны Python 3.11+ и Node.js 20+. На macOS используйте `python3`: команды `python` там обычно нет.

```bash
python3 -m pip install -r requirements.txt
./run_all.sh                        # ~15 мин: данные -> обучение -> кэш дня -> сборка фронтенда
python3 -m uvicorn app.api:app      # API + дашборд: http://localhost:8000
```

`run_all.sh` ждет CSV с data.mos.ru в `data/raw/` (наборы 60661, 60662, 60664, 60665, 60666). Если данных нет, API все равно поднимется и в `/api/health` ответит, какую команду запустить.

uvicorn запускается **из корня проекта**, иначе будет `No module named 'app'`.

Разработка фронтенда с горячей перезагрузкой (запросы к API идут через прокси Vite):

```bash
python3 -m uvicorn app.api:app --reload    # терминал 1
npm --prefix web run dev                    # терминал 2: http://localhost:5173
```

## Как устроено

```
 GPS-терминалы ─► service/ndtp_server ─► data_sources/gps_telemetry ─┐
 (NDTP по TCP)    (разбор пакетов)        (отметки -> остановки)       │ StopEvent
                                                                       │ (domain/schema.py)
 расписание ────► data_sources/mos_ru_schedule ────────────────────────┤
 (data.mos.ru)                                                         ▼
                                                 engine/stream_state (20 признаков в потоке)
                                                                       │
                     ┌─────────────────────────────────┬───────────────┴────────────┐
                     ▼                                 ▼                            ▼
              model/training               service/risk_service            replay_build
              (CatBoost: риск +            (живой риск по событиям)        (кэш записанного дня)
               регрессор под MAE)                      │                            │
                                                       │         service/replay_service
                                                       ▼                            │
                                                   api.py (FastAPI) ◄───────────────┘
                                                       │  JSON: кадры, KPI, тревоги
                                                       ▼
                                             web/ — дашборд на React
```

Признаки считает один и тот же класс `StreamState` и при обучении, и в живом сервисе. Модель в работе видит ровно то, на чем училась.

### Слои `app/`

Зависимости идут сверху вниз: верхний слой может импортировать нижние, но не наоборот.

| Слой | Что лежит | Правило |
|---|---|---|
| `domain/` | `StopEvent`, `ScheduleTables`, `DayContext`, `RiskPrediction` | Общий язык всех слоев. Ни от чего не зависит |
| `data_sources/` | data.mos.ru, байты NDTP, GPS → события, чтение parquet | Чистые преобразования: без сети и состояния |
| `simulation/` | Синтетический «факт» движения | **Временная заглушка**, уйдет с реальными данными |
| `engine/` | Признаки (`feature_definitions`), потоковое состояние (`StreamState`) | Не знает про ML-библиотеку |
| `model/` | Обертки CatBoost, метрики, загрузка артефактов, обучение | Остальной код не знает, что внутри CatBoost |
| `service/` | Живой риск, записанный день, TCP-приемник NDTP | Все, что держит состояние в памяти. Не знает про HTTP |
| `api.py` | FastAPI поверх `service/` | Тонкий слой: только маршруты и валидация |
| `replay_build.py` | Сборка кэша записанного дня | Запускается один раз, не во время работы API |
| `config.py` | Пути, пороги, порты | Единственное место для «магических чисел» |

Поменялся формат входных данных — правится один файл в `data_sources/`. `engine`, `model`, `service` и дашборд продолжают работать: они говорят на языке `domain/schema.py`, а не на именах колонок конкретного источника.

## Дашборд

`web/` — React + TypeScript + Vite. Главный принцип: **вся предметная логика на сервере**. Фронтенд не интерполирует положение машин, не знает порогов риска и не считает KPI. Он запрашивает готовый кадр и рисует его.

| Что | Где считается |
|---|---|
| Положение машин между остановками | `service/replay_service.py` |
| Уровни риска (низкий / средний / высокий) | `config.py: RISK_LEVELS` → API |
| KPI, список тревог, медленные перегоны, проверка сбывшихся тревог | `service/replay_service.py` |
| Подписи признаков и цифры в панели модели | `api.py: /api/model` |
| Проекция карты, зум, панорама, позиция ползунка | фронтенд (это отрисовка) |

Два режима:
- **Записанный день** — воспроизведение тестового дня: карта, шкала времени, карточка рейса.
- **Live** — риск по событиям, которые пришли в `POST /api/events`.

### API

| Эндпоинт | Что отдает |
|---|---|
| `GET /api/health` | Что доступно сейчас: записанный день, живой сервис, приемник NDTP |
| `GET /api/model` | Качество модели из `reports/metrics.json` |
| `GET /api/replay/day` | Метаданные дня и геометрия сети (запрашивается один раз) |
| `GET /api/replay/frame?t=&mode=&min_level=&trip=` | Кадр на момент `t`: машины, KPI, тревоги, медленные перегоны, карточка рейса |
| `GET /api/replay/timeline?mode=` | Сколько машин с высоким риском в каждый момент дня |
| `GET /api/live/snapshot` | То же, что кадр, но из живого потока событий |
| `GET /api/live/units` | Машины, подключенные по NDTP: последнее положение |
| `GET /api/risk?limit=&min_risk=` | Сырые прогнозы — для интеграций |
| `POST /api/events` | Пачка событий «машина прошла остановку» |
| `POST /api/context` | Погода и праздник на сегодня |

Кадр приходит колонками (`vehicles.lon[]`, `vehicles.level[]`, …) и сжимается gzip. Считается за доли миллисекунды: события всех рейсов лежат в плоских numpy-массивах, отсортированных по ключу `рейс × KEY_SPAN + время`, и положение всех машин находится одним `searchsorted`.

Если данных нет, API отвечает `503` с подсказкой, какую команду запустить, и подхватывает данные без перезапуска.

## Приемник NDTP

Вместе с API на порту **9201** поднимается TCP-сервер для бортовых терминалов. Проверен с эмулятором организаторов: пакеты разбираются, контрольные суммы сходятся. Положения машин — в `GET /api/live/units`.

Как запустить эмулятор, настройки, диагностика и что еще не сделано: **[docs/ndtp-emulator.md](docs/ndtp-emulator.md)**.

## ML под метрику хакатона

Отдельные скрипты в `scripts/` на данных организаторов (`data/hackathon/`). Прогнозируют отклонение от графика в секундах, метрика — MAE:

| Скрипт | Что делает |
|---|---|
| `explore.py` | Проверки данных и простые правила на test |
| `model_v1.py` | Проверка часового пояса, линейная модель и CatBoost на 3 признаках |
| `telemetry_features.py` | Совместимость: признаки переехали в `ml_service/features.py` |
| `model_v2.py` | CatBoost v2: признаки v1 + телеметрия. Файл сдачи и `models/hackathon_v2_catboost.cbm` |
| `model_classifier.py` | Вероятности early / ontime / late, сравнение с правилом «по регрессору» → `models/hackathon_v2_classifier.cbm` |
| `show_reasons.py` | 10 примеров «прогноз → причины» на test и покрытие причин |
| `check_service.py` | Проверка онлайн-оценки `cur_dev_s`: `python3 scripts/check_service.py test` (и `train`) |
| `model_city.py` | v3: «обстановка в городе» вместо `tgt_min_of_day` → `models/hackathon_v3_city.cbm` |
| `model_online.py` | Модели для live-режима (учатся на нашей оценке `cur_dev_s`) → `models/hackathon_v2_online*.cbm` |
| `ndtp_replay.py` | Проигрывает треки хакатона в приемник NDTP обычными пакетами, чтобы показать live без Docker |

Запуск из корня: `python3 scripts/model_v2.py`. Файлы сдачи попадают в `submissions/` (в git не хранится).

Код, который работает и в обучении, и в сервисе, лежит в пакете `ml_service/`:

| Модуль | Что делает |
|---|---|
| `features.py` | Единственное место, где считаются признаки (24 у v2 + «город» у v3) |
| `models.py` | Гиперпараметры и обучение регрессора и классификатора; `predict_class_probs(X)` |
| `reasons.py` | Причины прогноза: SHAP → фразы для диспетчера. Словарь `REASONS` правится без программиста |
| `cur_dev.py` | Онлайн-оценка `cur_dev_s` по телеметрии и расписанию (в живом потоке его никто не присылает) |
| `live.py` | Прогноз по потоку NDTP: буфер отметок, целевая остановка, признаки, модель. Питает режим Live дашборда, см. `docs/ndtp-emulator.md` |

Новые модели (классификатор, v3) сохраняются под своими именами и не затирают файлы v2. Обратите внимание: сам `model_v2.py` при запуске перезаписывает `models/hackathon_v2_catboost.cbm` (предсказания те же, байты файла отличаются).

## Результаты MVP (синтетика, отложенная неделя)

Главное — машины, которые **сейчас идут по графику**, но опоздают. Их диспетчер без прогноза не видит.

| | PR-AUC | Точность тревог при полноте 70% |
|---|---|---|
| CatBoost | 0.87 | 83% |
| Правило «смотреть на текущее опоздание» | 0.66 | 56% |

MAE отклонения через 10–15 минут, минуты:

| | Все машины | Идут по графику | Уже опаздывают |
|---|---|---|---|
| CatBoost (обучен под MAE) | **0.66** | **0.50** | **1.41** |
| «Опоздание сохранится» | 1.19 | 0.82 | 2.91 |
| «По расписанию» (0 мин) | 3.21 | 1.47 | 11.36 |

Это доказывает, что конвейер работает и модель использует сигналы сверх текущего опоздания. На реальных данных цифры будут другими: модель выучила правила симулятора.

## Тесты

Один раз на новом компьютере (venv, зависимости, Chromium для Playwright, pre-push хук):

```bash
./scripts/setup-tests.sh
```

Все проверки — те же, что запускает хук перед `git push` и GitHub Actions:

```bash
./scripts/test-all.sh
```

| Этап | Что проверяет |
|---|---|
| Backend unit | Признаки, метрики, сервисы, адаптеры data.mos.ru, GPS и NDTP |
| Backend integration | Настоящие `/api/...` через TestClient и NDTP по TCP. Покрытие не ниже 80% |
| Frontend | Vitest: клиент API, хуки, компоненты. Свои пороги покрытия |
| Build | Строгий TypeScript и сборка Vite |
| E2E | Playwright открывает собранный дашборд на настоящем FastAPI |

E2E работает на маленькой детерминированной фикстуре, поэтому не нужны ни `data/`, ни обучение.

```text
tests/
├── factories.py        общие фикстуры: записанный день, фейковый live, NDTP-пакеты
├── unit/               без HTTP и сети
├── integration/        FastAPI и NDTP TCP
└── e2e/server.py       сервер для Playwright
web/src/
├── test/fixtures.ts    общие ответы API для фронтенд-тестов
└── **/*.test.tsx       тесты рядом с кодом
```

Отдельные команды:

```bash
python3 -m pytest tests/unit -m unit
python3 -m pytest tests/integration -m integration
npm --prefix web run test:run
npm --prefix web run test:e2e
```

Python warnings настроены как ошибки. На Windows скрипты запускаются из Git Bash.

## Когда придут данные организаторов

1. **Связать `unit_id` с рейсом.** В пакете NDTP номера рейса нет. Нужна таблица или наряды от организаторов.
2. **Потоковая привязка отметок к остановкам.** `pings_to_events` в `app/data_sources/gps_telemetry.py` сейчас работает по треку рейса целиком.
3. **Передать события из приемника в `RiskService.ingest_events`** — тогда риск появится в Live.
4. Убрать `app.simulation.synthetic_telemetry` из `run_all.sh` и сложить реальные события в `data/processed/fact/` через `processed_repository.save_fact_day()`.
5. Погоду из симулятора заменить на реальную (Open-Meteo), праздники — на производственный календарь (`app/config.py: HOLIDAYS`).
6. Другой формат расписания (GTFS, другой город) — новый класс по образцу `MosRuScheduleSource` (протокол `ScheduleSource` в `app/data_sources/base.py`).
7. Переобучить: `python3 -m app.model.training`, затем `python3 -m app.replay_build`.

## Ограничения MVP

- Состояние живого сервиса и приемника NDTP — в памяти одного процесса. Для работы нужен Redis или аналог.
- Записанный день целиком держится в памяти API. Это демо-режим, в работе нужен Live.
- Маршруты на карте — прямые между остановками: в данных data.mos.ru нет трасс.
- CORS открыт на все источники, NDTP слушает все интерфейсы. Для работы сузить `allow_origins` и `NDTP_HOST`.
