# Предиктор задержек наземного транспорта — MVP

Прогнозирует, опоздает ли машина больше чем на 3 минуты через 10–15 минут, и показывает риск на диспетчерском дашборде.

**Статус:** расписание реальное (data.mos.ru), фактическое движение пока смоделировано. Весь конвейер готов к подмене источника на телематику организаторов.

## Как устроено

```
GPS-отметки (NDTP) ──► ingest.py ──► события «машина прошла остановку»
                                          │
плановое расписание ──────────────────────┤
(data.mos.ru)                             ▼
                                   features.py (потоковый расчет признаков)
                                          │
                          ┌───────────────┼────────────────┐
                          ▼               ▼                ▼
                     train.py         api.py        export_dashboard.py
                   (CatBoost)     (веб-сервис)       (дашборд)
```

Признаки считаются одним и тем же классом `StreamState` и при обучении, и в сервисе, поэтому модель в проде видит ровно то, на чем училась.

## Файлы

| Файл | Что делает |
|---|---|
| `src/load_schedule.py` | Читает 5 наборов data.mos.ru, чинит время после полуночи, берет 49 самых загруженных маршрутов (35 автобусных, 14 трамвайных) |
| `src/simulate.py` | **Временная заглушка.** Генерирует «факт» на 28 дней: пики, проблемные перегоны, дождь, инциденты, эффект «пачки» |
| `src/ingest.py` | Адаптер GPS → остановки. Проверен на синтетических треках: 99% остановок, ошибка времени ~5 с |
| `src/features.py` | 20 признаков: текущее опоздание и его тренд, разрыв с впереди идущей машиной, как сейчас едут перегоны впереди (по другим машинам), типичная скорость перегонов в этот час, погода, календарь |
| `src/train.py` | Честное разбиение по времени: 7 дней профиль, 14 обучение, 7 тест |
| `src/api.py` | FastAPI: `POST /events`, `GET /risk`, `POST /context` |
| `src/export_dashboard.py` | Прогоняет тестовый день и собирает `dashboard/dashboard.html` |

## Запуск

```bash
pip install -r requirements.txt
./run_all.sh                       # ~15 минут
cd src && uvicorn api:app --reload # сервис
```

## Результаты (синтетика, отложенная неделя)

Главная метрика — машины, которые **сейчас идут по графику**, но опоздают через 10–15 минут. Именно их диспетчер не видит без прогноза.

| | PR-AUC | Точность тревог при полноте 70% |
|---|---|---|
| CatBoost | 0.87 | 83% |
| Правило «смотреть на текущее опоздание» | 0.66 | 56% |

Эти цифры доказывают, что конвейер работает и модель использует сигналы сверх текущего опоздания. Точность на реальных данных будет другой: модель выучила правила симулятора.

## Когда придут данные организаторов

1. Написать `decode_ndtp()` в `ingest.py` под их формат.
2. Если в телематике нет номера рейса — сопоставить машину с рейсом по наряду или по «маршрут + направление + ближайший плановый рейс».
3. Убрать `simulate.py` из конвейера, положить реальные события в `data/processed/fact/`.
4. Заменить погоду из симулятора на реальную (Open-Meteo), праздники — на производственный календарь.
5. Перезапустить `train.py` и `export_dashboard.py`.

## Ограничения MVP

- Сервис хранит состояние в памяти одного процесса; для прода нужен Redis или аналог.
- Дашборд — воспроизведение дня; в проде он должен опрашивать `GET /risk`.
- Геометрия маршрутов — прямые между остановками (в наборах data.mos.ru нет трасс).
