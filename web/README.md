# Контроль движения — frontend

React + TypeScript + Vite. Работа с HTTP централизована в `src/api/client.ts`; существующие backend endpoints сохранены.

## Запуск

```sh
cd web
npm install
# Только если .env ещё не создан:
cp .env.example .env
npm run dev
```

`VITE_USE_MOCKS=true` в `web/.env` включает демонстрацию без backend: 24 синтетических ТС, 6 маршрутов, движение, риски, прогнозы на 12 минут, причины и проблемные участки. Московские названия — только иллюстративные подписи. Геометрия, расписание, движение и метрики не описывают реальные маршруты. На экране постоянно виден `DEMO DATA`.

`VITE_USE_MOCKS=false` использует существующий сервис. Vite проксирует `/api` на `http://127.0.0.1:8000`; альтернативный адрес — `VITE_API_BASE`. Перезапускайте Vite после изменения `.env`. Для production параметры задаются перед сборкой. `.env` исключён из Git.

## Карта: граница для будущего подключения провайдера

В этой итерации dashboard использует `MapViewport` с интерактивной Canvas-схемой. Настоящий провайдер не подключается. Существующие `src/maps/yandex.ts` и `TransportMap.tsx` сохранены без изменений и сейчас не вызываются dashboard.

`MapViewport` принимает `day`, `frame`, `selected`, `focusToken`, `focusReady`, `onSelect` и `display`. Его `map-provider-slot` — место для будущей географической подложки. Сеть, позиции, риски, проблемные участки и выбранное ТС остаются отдельными данными. При подключении Yandex используйте его географическую проекцию/объекты для этих слоёв: текущая Canvas-схема имеет собственную проекцию, её пиксели нельзя непосредственно накладывать на географическую карту.

Поддерживаются панорамирование, масштаб, выбор, круг/треугольник/ромб/квадрат для уровней риска и внешняя обводка выбранного ТС. Подписи размещаются с учётом пересечений. Проблемный участок выбранного ТС дополнительно выделяется, когда его индекс известен.

## Данные и стабильность интерфейса

- Отрицательное `delay` означает движение раньше расписания, положительное — опоздание. UI объясняет знак текстом. «По графику» используется только как допуск отображения: абсолютное отклонение меньше 0.1 минуты; исходные данные и расчёты не меняются.
- Sidebar получает завершённый снимок раз в 4 секунды независимо от частых обновлений карты. При перемотке/остановке Replay и первом выборе сведения показываются сразу. KPI также используют снимок; выбранная карточка сохраняет ID.
- Порядок инцидентов стабилен внутри приоритетных групп. Первоначально критические — от 90%; затем используется гистерезис: переход в критические от 93%, выход ниже 87%. Колебания на 1–2% не переставляют карточки. Это приоритет UI, не изменение вероятности или backend sorting.
- Риск показывается целым процентом, время — максимум с одним десятичным знаком. Изменившееся значение получает краткую мягкую подсветку.
- Replay стартует с ×10; доступны ×1/×5/×10/×30/×60. Выбор ТС ставит Replay на паузу. Timeline поддерживает мышь, клавиатуру и подсказку с временем/числом ТС высокого риска.
- Состояние соединения рассчитывается от последнего успешного ответа. Во время активного потока данные старше 15 секунд отмечаются устаревшими. При ошибке остаётся последнее известное состояние и доступен повтор запроса. Для намеренно приостановленного Replay показывается состояние паузы.

Причина, участок, время события, скорость, простой и рекомендации в Demo синтетические. Неизвестные production-поля не подменяются примерными значениями. Текущий production Live передаёт KPI/alerts без координат: на схеме выводится объяснение, а доступные прогнозы остаются в панели. Поиск в production ограничен ТС из доступных ответов.

## Отображение и управление

Поиск работает по маршруту или ID ТС, в том числе с клавиатуры. Выбор результата сбрасывает фильтры, мешающие его показать. Фильтры транспорта/риска управляют схемой, фильтры инцидентов — стабильными приоритетными группами. Выбранное ТС остаётся видно даже при отключении его уровня риска.

В «Отображение» доступны стандартная, контрастная, адаптированная для дальтонизма и своя палитры; собственные цвета задаются native color input. Можно включать подписи, номера маршрутов, проблемные участки и низкий риск, менять плотность. Настройки валидируются и сохраняются в `localStorage` под ключом `transport-dashboard-display-v1`. «Сбросить цвета» восстанавливает стандартную палитру, сохраняя прочие настройки. При недоступном storage настройки работают в пределах сессии.

## Проверки

```sh
npm run build
node --experimental-strip-types --test tests/*.test.mjs
```

Для тестов нужен Node.js 22.6+. Проверяются синтетическая сеть/координаты, связь тревог и карточек с проблемными сегментами, фильтры, движение, Timeline, семантика отклонений, стабильность сортировки и валидация настроек.

Для ручной проверки: 1440×900 и 1280×800; Replay/Live; поиск маршрута и ID; фильтры; выбор и возврат; палитры/custom/reset и перезагрузка; tooltip Timeline; backend offline и последнее известное состояние. Сценарные оценки ML в этой итерации не добавляются.
