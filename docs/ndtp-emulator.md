# NDTP: приемник телематики и эмулятор организаторов

## Что это и зачем

Бортовые терминалы в автобусах передают положение машины по протоколу **NDTP**. Это бинарный протокол поверх TCP: терминал сам подключается к серверу и раз в несколько секунд присылает пакет с координатами, скоростью и показаниями датчиков.

Организаторы дали **эмулятор терминала**: Docker-образ `ndtp-telemetry-emulator.tar` и спецификацию `Emulator-and-Telematic-Packets-Specification.md`. Эмулятор говорит по тому же протоколу, что и настоящий терминал. С ним приемник можно проверить до того, как появятся живые машины.

Наша сторона — **приемник** (`app/service/ndtp_server.py`). Он слушает TCP-порт, разбирает пакеты и хранит последнее положение каждой машины.

```
 эмулятор (Docker)        TCP :9201       наш приемник            HTTP :8000
 или терминал автобуса ─────────────────► service/ndtp_server ──► GET /api/live/units
      unitId, NDTP                        (последнее положение      (JSON для дашборда)
                                           каждой машины)
```

**Важно:** эмулятор с `autoGenerate: true` присылает **случайные** координаты около Москвы: точка блуждает по курсу, никакого маршрута за ней нет. Так проверяется канал и формат, а не данные. Настоящие треки появятся, когда организаторы подключат реальные терминалы или загрузят в эмулятор реальный маршрут.

## Проверка за 5 минут

Нужен Docker Desktop. Если `docker info` пишет `failed to connect to the docker API`, сначала запустите приложение: `open -a Docker` и подождите, пока значок кита перестанет мигать.

**Терминал 1. API вместе с приемником** (из корня проекта):

```bash
python3 -m uvicorn app.api:app
```

В логе должна быть строка `NDTP-приемник слушает 0.0.0.0:9201`.

**Терминал 2. Эмулятор** (из папки, где лежит `.tar`):

```bash
docker load -i ndtp-telemetry-emulator.tar     # один раз
docker run --rm -p 18080:18080 --add-host=host.docker.internal:host-gateway \
  --name ndtp-emu ndtp-telemetry-emulator:1.0
```

**Терминал 3. Отправка** — сказать эмулятору, куда слать пакеты:

```bash
curl -X POST localhost:18080/api/config -H 'Content-Type: application/json' -d '{
  "targetHost": "host.docker.internal",
  "targetPort": 9201,
  "units": [{"unitId": 1166336, "intervalMs": 5000, "autoGenerate": true, "cells": []}]
}'
```

Через 5–10 секунд:

```bash
curl localhost:8000/api/live/units
```

Ожидаемый ответ (числа будут другими):

```json
{
  "listening": true, "port": 9201,
  "stats": {"connections": 1, "frames": 4, "fixes": 3, "ignored": 1, "crc_errors": 0},
  "units": [{
    "unitId": 1166336, "connected": true, "packets": 3, "lastSeenSec": 3.2,
    "position": {"lon": 37.53, "lat": 55.73, "valid": true, "gpsTime": 1790355730,
                 "speed": 12, "course": 321}
  }]
}
```

Остановить эмулятор: `Ctrl+C` в терминале 2 (контейнер с `--rm` удалится сам). Остановить отправку, не гася контейнер: тот же `POST /api/config` с `"units": []`.

Несколько машин: добавьте в `units` элементы с разными `unitId`. На каждый эмулятор откроет отдельное TCP-соединение.

## Что проверено

| | Статус |
|---|---|
| Handshake `NPH_SGC_CONN_REQUEST`, версия 6.2 | принимается, пишется в лог |
| Realtime `NPH_SND_REALTIME`, ячейка навигации `G6CellNav00` | разбирается |
| CRC-16/Modbus с переставленными байтами | сходится с настоящим эмулятором (`crc_errors: 0`) |
| Переподключение терминала | машина остается «на связи» |
| Пакет пришел частями или несколько пакетов сразу | собирается правильно |
| Мусор в потоке, битая CRC | пакет отбрасывается, следующий не теряется |

Автотесты (Docker не нужен, пакеты собираются по спецификации в `tests/factories.py`):

```bash
python3 -m pytest tests/unit/test_ndtp_protocol.py tests/integration/test_ndtp_server.py -v
```

## Как устроен код

| Файл | Что делает |
|---|---|
| `app/data_sources/ndtp_protocol.py` | Только байты: поиск кадров в потоке TCP, проверка CRC, разбор handshake и навигации. Без сети, тестируется отдельно |
| `app/service/ndtp_server.py` | TCP-сервер на asyncio: соединения, состояние машин (`unit_id` → последнее положение), счетчики |
| `app/api.py` | Поднимает приемник вместе с FastAPI, отдает `GET /api/live/units`, статус в `GET /api/health` |

Из пакета берется только навигация: время фиксации, широта, долгота, признак достоверности, скорость, курс. Ячейки топлива, CAN, температуры и прочих датчиков для прогноза задержек не нужны и пропускаются.

Имена полей отметки совпадают с колонками выгрузки организаторов (`unit_id`, `gps_time`, `lon`, `lat`, `location_valid`). Живой поток и файлы из выгрузки приводятся к одному виду.

## Настройки

Переменные окружения (значения по умолчанию в `app/config.py`):

| Переменная | По умолчанию | Смысл |
|---|---|---|
| `NDTP_PORT` | `9201` | TCP-порт приемника |
| `NDTP_HOST` | `0.0.0.0` | На каком интерфейсе слушать. `0.0.0.0` нужен, чтобы достучался Docker, но так порт виден всей локальной сети. В общей сети ставьте `127.0.0.1` |
| `NDTP_VERIFY_CRC` | `1` | `0` — не проверять контрольную сумму. Только для диагностики |

Пример: `NDTP_PORT=19201 python3 -m uvicorn app.api:app`. Эмулятору тогда нужен `"targetPort": 19201`.

Приемник без API, с выводом каждого пакета в консоль:

```bash
python3 -m app.service.ndtp_server
```

## Если не работает

| Симптом | Причина и что делать |
|---|---|
| `failed to connect to the docker API` | Docker Desktop не запущен: `open -a Docker` |
| `open ndtp-telemetry-emulator.tar: no such file` | Команда запущена не из папки с файлом: `cd ~/Downloads` |
| `/api/health` → `"ndtp": {"ready": false, "error": "не удалось открыть …"}` | Порт 9201 занят, например вторым экземпляром API. Остановите его или смените `NDTP_PORT` |
| В `units` пусто, в логе API нет `подключение` | Эмулятор не достучался: проверьте `targetHost: host.docker.internal` и флаг `--add-host` в `docker run` |
| `подключение` есть, `fixes` не растет, в логе `CRC не сошлась` | Терминал считает CRC иначе, чем в спецификации. Запустите с `NDTP_VERIFY_CRC=0` и пришлите значения из лога |
| `ModuleNotFoundError: No module named 'app'` | uvicorn запущен не из корня проекта |

## Чего еще нет

- **Ответа терминалу.** Формата ответа в спецификации нет, эмулятор ответы не читает. Настоящим терминалам подтверждение, возможно, понадобится.
- **Связи с моделью.** Положения хранятся, но в прогноз опозданий не идут. Нужны:
  1. сопоставление `unit_id` → маршрут/рейс (в пакете NDTP номера рейса нет — таблицу или наряды должны дать организаторы);
  2. потоковая привязка отметок к остановкам (`pings_to_events` в `app/data_sources/gps_telemetry.py` сейчас работает по треку рейса целиком);
  3. передача получившихся событий в `RiskService.ingest_events`. Тогда риск появится в `/api/live/snapshot` и на дашборде.
- **Хранения истории.** В памяти только последнее положение каждой машины; после перезапуска API состояние пустое.
