# Приложение Г Примеры запросов и ответов

Примеры фиксируют форму HTTP-контрактов. Значения для одного условного рейса предназначены для чтения и разработки интеграции; они не являются прогнозом реального рейса. Пустые массивы в примерах допустимы. Полный актуальный набор входных параметров публикуется в openapi.json, а семантика ошибок и единиц приведена в разделе 5.

## Проверка готовности

```http
GET /api/health
```

```json
{
  "ok": true,
  "sources": {
    "replay": {"ready": true, "error": null},
    "live": {"ready": true, "error": null}
  },
  "tripsInSchedule": 28537
}
```

Это фактические значения готовности и объёма расписания контрольного запуска. При ready=false HTTP 200 и ok=true могут сохраниться. Система мониторинга проверяет требуемый источник явно.

## Метрики модели

```http
GET /api/model
```

```json
{
  "horizon": "10–15 мин", "threshold": 3.0, "recall": 70,
  "precision": 83, "baselinePrecision": 56,
  "prAuc": 0.8666, "baselinePrAuc": 0.658,
  "testSize": 566680,
  "features": [
    {"key": "delay_now", "label": "Текущее опоздание",
     "importance": 33.7, "share": 1.0}
  ]
}
```

Для компактности показан один признак с сокращённой подписью. API возвращает до пяти признаков с полными подписями. share — отношение важности к максимальной важности в этом списке, а не доля среди всех признаков. Строка horizon является меткой интерфейса и не подтверждает соблюдение строгого горизонта.

## Метаданные записанного дня

```http
GET /api/replay/day
```

```json
{
  "date": "2026-09-03", "dow": 3,
  "rain": {"level": 0.0, "start": 0.0, "end": 0.0},
  "threshold": 3.0, "tMin": 480.0, "tMax": 490.0,
  "horizonLabel": "10–15 мин",
  "riskLevels": {"mid": 0.3, "high": 0.6},
  "modes": [
    {"id": 0, "key": "bus"}, {"id": 1, "key": "tram"},
    {"id": 2, "key": "trolley"}, {"id": 3, "key": "other"}
  ],
  "trips": 1,
  "network": {
    "stops": [[37.61, 55.75], [37.62, 55.76]],
    "segments": [[0, 1]]
  }
}
```

Пример соответствует масштабу фикстуры с двумя остановками. В ответе контрольного запуска — 15 443 рейса, 1 636 остановок и 1 691 перегон. Координаты stops имеют порядок longitude, latitude; сегмент ссылается на индексы массива stops.

## Шкала времени

```http
GET /api/replay/timeline?mode=bus
```

```json
{
  "tMin": 480.0, "tMax": 490.0,
  "bins": [{"t": 480.0, "high": 1}, {"t": 485.0, "high": 1}],
  "ticks": [{"t": 480.0, "label": "08:00"}],
  "rain": null
}
```

bins идут с шагом пять минут. ticks содержат часовые подписи. Данные шкалы зависят от фильтра mode, но не от выбранной карточки рейса.

## Отправка событий

```http
POST /api/events
Content-Type: application/json
```

```json
[
  {"trip_id": "trip-001", "route_id": "route-42", "direction_id": "0",
   "k": 0, "stop_id": "stop-001", "plan": 480.0, "fact": 481.2}
]
```

```json
{"accepted": 1, "scored": 1}
```

Ответ scored=1 возможен, если trip-001 существует в расписании и имеет цель прогноза. При неизвестном рейсе scored=0. Для запроса с пропущенным plan или другим обязательным полем API возвращает 422 с диагностикой Pydantic. Повторная отправка не имеет гарантии идемпотентности.

## Обновление контекста

```http
POST /api/context
Content-Type: application/json
```

```json
{"rain": 0.7, "holiday": 1}
```

```json
{"ok": true}
```

Изменение влияет на признаки последующих событий. Оно не пересчитывает автоматически уже сохранённые прогнозы всех рейсов.

## Список рисков Live

```http
GET /api/risk?limit=10&min_risk=0.6
```

```json
[
  {"trip_id": "trip-001", "route": "42", "mode": "bus",
   "stop_id": "stop-001", "t": 481.2,
   "delay_now": 1.2, "risk": 0.8}
]
```

Список отсортирован по риску в убывающем порядке. Число элементов ограничивается limit; при отсутствии подходящих прогнозов возвращается []. Значение risk — доля, а не процент.

## Диспетчерский срез Live

```http
GET /api/live/snapshot
```

```json
{
  "clock": "08:05", "tracked": 1,
  "kpi": [
    {"key": "onLine", "label": "рейсов под наблюдением", "value": "1"},
    {"key": "high", "label": "высокий риск через 10–15 мин",
     "tone": "high", "value": "1"},
    {"key": "late", "label": "уже опаздывают", "value": "0"},
    {"key": "hit", "label": "ранних тревог сбылось", "value": "—"}
  ],
  "alerts": [{
    "tripId": "trip-001", "route": "42", "mode": "bus",
    "dest": "Конечная", "stop": "Начальная", "delay": 1.2, "risk": 80
  }]
}
```

Необязательная hint у последнего KPI опущена. clock — текущее время процесса API, а t в сыром прогнозе — время события. Эти значения не следует считать взаимозаменяемыми. Live tripId имеет строковый тип, в отличие от индекса Replay.
